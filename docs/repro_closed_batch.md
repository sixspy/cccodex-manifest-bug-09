# 拒登复现单：已闭合批仍能灌入新对象（manifest-bug-09）

## 1. 缺陷现象

- 已闭合批次还能通过 `POST /api/batches/{id}/objects` 写入新对象，对象列表冒出状态为“已登记”的行。
- 闭合时固化的 `closed_object_count` 与实际行数脱节，清洗入库只认“已登记”行的口径被污染，可见性对账错位。
- 并发“灌数 vs 闭合”缺库级写锁，存在双写窗口。

根因在初始快照即植入：`app/services/objects.py` 旧逻辑把“已闭合”也放进允许登记的状态集合（代码注释 `silent: allow register even when closed`），页面端按钮也始终可点。

## 2. 读态拍板（两种读态只钉死一条，禁止混用）

| 方案 | 说明 | 是否采用 |
|----|------|------|
| A. 提交瞬间读库内最新批次态 | 服务端在写事务内读取批次行并当场判定 | **采用** |
| B. 开页瞬时冻住批次态再判 | 详情页打开时快照批次态，提交时按快照判定 | 不采用 |

采用 A 的理由：闭合与登记在同一把库写锁上串行化，临界闭合的放行结果确定、可复现；批次态与可登记门槛天然同源（同事务同一条 `landing_batches` 行），不存在开页后批次被他人闭合、页面仍按旧快照放行的窗口。全链路（服务、页面、扫库台）只标注这一种读态来源：**提交瞬间库内最新批次态**。

## 3. 修复口径

1. **服务端一次拦截**：`register_object` 在 `BEGIN IMMEDIATE` 立即写事务内读取批次态，仅“收集中”放行；“已闭合”返回 409，短句 `批次已闭合，拒绝登记新对象`，并带 `reason=BATCH_CLOSED` 与 `read_source`。
2. **同源门槛**：批次详情接口返回 `register_gate`（同读态来源、同拒因码），登记详情页据此亮拒因条并禁用表单；批次卡片、对象列表脏行、去重扫库台全部使用同一套拒因码。
3. **存储层兜底**：SQLite 触发器 `trg_landing_objects_gate` 禁止向非“收集中”批次 INSERT 对象，绕开应用层直插同样拒写。只改提示文案、不碰拦截逻辑的“半修”无法通过。
4. **并发不双写**：登记与闭合共用 `locked_write()`（`BEGIN IMMEDIATE` + `busy_timeout=5000`），抢同一写锁串行化；闭合后到达的登记在锁内读到“已闭合”即拒。
5. **去重扫库台**：清洗入库口径只收“收集中”批内的“已登记”行；闭合/作废批里的已登记脏行按 `BATCH_CLOSED`/`BATCH_VOID` 同因拒收；同内容指纹跨批聚组去重只在可入库行内统计。护栏生效后复跑扫库，拒登行数不再增长。

## 4. 复现 / 验证步骤

```bash
python -I scripts/repro_closed_batch.py          # 独立复现单（临时库，全程断言）
pytest tests/test_closed_gate.py -v              # 接口/触发器/并发/扫库回归
pytest                                            # 全量基线不回归
```

并发复现要点：7 个登记线程与 1 个闭合线程在同一 Barrier 后同时放行，跑完断言闭合批对象数等于 `closed_object_count`、无任何“已登记”残留、被拒登记全部带 `BATCH_CLOSED`。

## 5. 页面四处对照

| 位置 | 展示 |
|----|------|
| 批次卡片（落地批次列表） | 非收集中批标红 `拒登 · BATCH_CLOSED/BATCH_VOID` |
| 登记详情 | 顶部拒因条：拒因码 + 短句 + 读态来源，表单与写入按钮禁用 |
| 对象列表 | 闭合/作废批内若有“已登记”脏行，入库口径列标同一拒因 |
| 去重扫库台 | 拒登脏行表与登记接口同因同短句，并标注同一读态来源 |
